#### DRF view runtime (`plane-drf`)

The per-route policy is generated from Django's own introspection
(`tools/inventory/routes.py` records `base_family`, `use_read_replica`,
`TimezoneMixin`, `http_method_names`, parser/renderer/metadata classes,
`get_view_name()`/`get_view_description()`, lifecycle overrides,
`allow_permission` per method, the `BaseViewSet` guard's action half and the
`OPTIONS` action field maps). `crates/plane-drf` embeds `routes.json`, refuses
to start on an unknown class or an unimplemented override, and is the only way
a handler becomes reachable: `Registry::viewset(...).action(...)` /
`api_view(...).method(...)` / `django_view` / `function`, with paths, methods
and every security class taken from the table. Dispatch reproduces
`APIView.initial` order (negotiation → authenticators → permissions →
throttles → timezone → family `initial` → `allow_permission` → handler),
`handle_exception` per family and `finalize_response` (`Allow` in
`http_method_names` order, `X-RateLimit-*` on `/api/v1/`). Plain Django views
and function views skip DRF entirely and use `View.dispatch`.

Verification: `scenarios/policy-probe.yaml` (5,451 steps; generated by
`tools/policy/gen_policy_scenario.py`, fixture by `gen_fixture.py`) run with
`plane-api --features policy-probe`:

```sh
cargo build -p plane-api --features policy-probe
./target/debug/difftest run --scenario scenarios/policy-probe.yaml --a django --b rust
```

The harness treats a B response carrying `X-Plane-RS-Probe: handler` as a
pass-through: if A denied at the policy (401/405/406/415/429, or a 403 with one
of the policy bodies) it is a DIFF; otherwise the step is `reached-handler` and
its response and DB/Redis/Celery side effects are ignored. Redis keys written
by a reached-handler step are remembered and excluded from later steps (their
TTL would otherwise change on A alone). Writes are the final block; `DELETE`
steps name objects that do not exist, and the four routes that destroy shared
state (user deactivate, workspace delete, project/workspace leave) run only
against per-route disposable objects.

Result (2026-11-16, two consecutive runs, Django vs `plane-api
--features policy-probe`): **5,451 steps; 2,287 policy denials compared; 2,555
reached-handler; 0 mismatches; exit 0 both times.** `skeleton.yaml` (Django vs
Rust) and `auth-session.yaml` (Django vs Django, as its header says until
Phase 6) still pass.

## Follow-ups (not blocking)

- Performance: loading session + user costs ~1.27 ms p50 per authenticated request (two
  sequential queries over the Docker VM network). Candidates: one round trip using the
  `sessions.user_id` column, then verify it against the decoded `_auth_user_id`.
- `plane-auth` has its own small JSON writer for Django's signing serializer
  (`ensure_ascii=True`, compact). Move it into `plane-serde` as a dialect.
- `routes.py` `params` now include converters from enclosing includes (fixed).
- The policy-probe fixture contains session payloads signed with the dev `SECRET_KEY`, so
  the probe runs locally only; regenerate with `tools/policy/gen_fixture.py`.
- Harness: JSON volatile rules are name-scoped, so every JSON key `token` must have the API
  token shape; the fixture uses 64-hex tokens everywhere to fit. Make the rules path-scoped.
- Issue list SQL is DB-bound (grouped list 18.9 ms Rust vs 37.5 ms Python on the dev stack):
  profile the generated statements with `EXPLAIN ANALYZE` in the performance pass.
- `ViewCtx` has no storage (`plane-storage`) or outbound HTTP (`plane-net`) handle yet;
  wave 2 asset code builds them per module. Add accessors like `cache()`/`celery()`.
- Rows ordered by Django without a unique tiebreak (or with no `ORDER BY`) come out in
  the planner's order. Rust issues the same query shape so the planner behaves the same,
  but that order is not a guarantee on either side.
- `plane-auth` is a direct dependency of `plane-http-app` only to build a `PermCtx`
  (no id-only constructor in `plane-permissions`).

## Open questions for the owner

1. `SECRET_KEY` unset: Django falls back to a random key per process (sessions and encrypted
   instance configuration then break across processes). Default taken: Rust does the same
   and logs the same critical message, because behaviour must match. Say if Rust should
   refuse to start instead.
2. Scout APM (`SCOUT_MONITOR`, `SCOUT_KEY`) is a Python agent. Default taken: not ported;
   the variables are accepted and ignored.
3. boto3 resolves S3 credentials through its full chain (env, profile files, instance
   roles). Default taken: the Rust client supports env credentials plus the container and
   instance metadata providers; profile files only if a deployment needs them. Decide at
   Phase 5.
4. Celery arguments: some callers pass UUID objects (serialised as kombu
   `{"__type__":"uuid",...}` envelopes), others strings. Default taken: the Rust publisher
   reproduces each call site's types exactly.

## Suspected upstream bugs, ported as they are

- `GET /api/workspaces/` returns 400 `{"error": "The required key does not exist."}`:
  `allow_permission` reads `kwargs["slug"]` on a route without it
  (`plane/app/permissions/base.py:62`). The web app uses `/api/users/me/workspaces/`.
- A CSRF rejection on Django form views returns 200 with an HTML page
  (`plane/authentication/views/common.py:39-45`).
- The admin session cookie is chosen by `"instances" in request.path`, a substring test
  (`plane/authentication/middleware/session.py:23,43`).
- `APPEND_SLASH` answers a POST with 301 and drops the body at `DEBUG=0`.
- With `NUM_PROXIES` unset, the throttle identity collapses `X-Forwarded-For`, so clients
  behind a proxy share one bucket (`rest_framework/throttling.py:40`).
- Pages: `project_ids` aggregates over the visibility join, so it lists projects whose
  `ProjectPage` link is soft-deleted, and its `~Q(projects__id=True)` filter compiles to a
  sentinel UUID comparison (`plane/app/views/page/base.py:127-140`). `label_ids` ignores
  `page_labels.deleted_at`. The visibility join ignores `project_members.deleted_at`.
  `live-access` answers 404 on every denial and matches `action` case-sensitively
  (`plane/app/views/page/live.py`).
- `ApiKeyRateThrottle` puts the raw API token in the Redis key (`plane/api/rate_limit.py:23`).
- `is_allowed_origin` compares host only, not scheme (`plane/authentication/session.py:51`).
- `project_invitations.delay(...)` is called on a list and the task module is never
  imported (`plane/app/views/project/invite.py:121`): that route creates invites then 500s.
- Draft-to-issue conversion publishes `project_id="None"`, dropped by `issue_activity`.
- `recent_visited_task` trims at `count == 20`, not `>=`.
- `delete_old_s3_link` is scheduled twice (01:30 and 03:45).
- `webhook_send_task` "backoff" is uniform 0–600 s (retry_backoff hits the 600 s cap).
- `hard_delete` probably violates the `issue_activities` FK (deletes issues before their
  `DO_NOTHING` activity rows; `plane/bgtasks/deletion_task.py:150,164`). Verify on a real
  database before porting.
- `Workspace.delete` can overflow the 48-character slug when appending `__<epoch>`
  (`plane/db/models/workspace.py:156-174`).
- API-created comment descriptions get NULL audit columns (`plane/db/models/issue.py:493-508`).
- Cascaded soft deletes in Celery null `created_by`/`updated_by` (no request user).
- Default project states are bulk-created with empty `slug` (bypasses `State.save`).
- Seeded issues: `IssueSequence.sequence` stays 1 while `sequence_id` is max+1.
- Seed defaults that contradict readers: `ENABLE_MAGIC_LINK_LOGIN` seeded `"0"`, read with
  default `"1"`; `EMAIL_FROM` seeded `""`; `GITLAB_HOST` seeded NULL.
- Duplicate DRF api-root at `/api/v1/workspaces/{slug}/` (invitations router wins).
- `plane/api/urls/schema.py` and `estimate.py` are never included (dead v1 routes).
- Members of a soft-deleted workspace still pass workspace permission checks
  (`WorkspaceMember.objects.filter(workspace__slug=…)` does not filter the workspace's
  `deleted_at`).
- A page owner bypasses `ProjectPagePermission`'s method table (a MEMBER/GUEST owner can
  `DELETE` their page; `plane/app/permissions/page.py:57-59`).
- `allow_permission` on the attachment collection routes reads `kwargs["pk"]`, so `DELETE`
  there is a 400 `The required key does not exist.` for any project member.
- `InstanceAdminPermission` uses `role >= 15`; `WorkspaceOwnerPermission` never reads
  `Workspace.owner`; the v1 member endpoint's `HEAD`/`OPTIONS` are admin-only.
- `/api/v1/` `BaseViewSet` views (invitations, stickies) are throttled by `AnonRateThrottle`,
  so API-key callers are not rate limited there and get no `X-RateLimit-*` headers.
- `ApiKeyRateThrottle` reads `:1:None` from Redis on every keyless request.
- `DELETE /api/users/me/` and `members/leave/` deactivate memberships (by design, noted
  because they destroy fixture state).
- `SocialLoginConnection.medium` is `CharField(default=None)` on a NOT NULL column.
- Cache invalidation: label/estimate `partial_update`/`destroy` invalidate without the
  user part of the key, so every user's cached list stays stale for up to 2 h;
  `/api/instances/admins/` is cached and never invalidated; most invalidated paths are
  never cached; a cache hit on `GET /api/instances/` loses `Cache-Control`; invalidation
  uses `KEYS`.
- Read endpoints that always 500: `GET` favourite detail, home preference detail,
  `/api/users/last-visited-workspace/` (reads a field that lives on `Profile`),
  `/api/public/workspaces/{slug}/project-boards/`, instance admin detail, issue attachment
  detail, the v1 `.{format}` routes for invitations and stickies.
- Public issue reactions and votes always return `[]` (wrong lookup kwargs).
- `IssueVersion.log_issue_version` and `IssueDescriptionVersion.log_issue_description_version`
  always fail and write nothing (`plane/db/models/issue.py:743,806`).
- `is_valid_uuid` accepts only version-4 UUIDs, so `issue_activity` drops other ids.
- Issue filters: `type` overwrites `state_group`; POST `intake_status` reads
  `inbox_status`; `logged_by` always 500s; `order_by=priority` is low-first in
  `IssueViewSet` but urgent-first in `IssueListEndpoint`; sub-grouped pages 500 on a NULL
  group value; grouped `total_count` counts model rows, not issues.
- Celery `saferepr` truncation can emit unbalanced brackets in `argsrepr`.
